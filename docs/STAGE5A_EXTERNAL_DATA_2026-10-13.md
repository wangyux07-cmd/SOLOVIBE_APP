# 阶段五 A：地址、步行导航与商家资料接入记录

> 日期：2026-10-13。依据 [V2 方案](AI_AGENT_REDESIGNED_PLAN_V2.md)实施的外部数据与证据契约增量；阶段五的局部调整、数据生命周期和发布工作尚未完成。

## 本轮实际改动

- 保留真实高德地理编码、周边 POI 检索和步行路线；路线观察现在同时保存起点坐标、终点坐标及目标 POI ID，以便检查证据与目标地点是否对应。
- 商家详情改用高德 POI 2.0 ID 查询的 `business` 字段。取得且与同一 POI 的 ID、坐标、名称、地址一致时，展示评分、参考人均、登记周营业时段、今日登记时段和最多六条特色标签；每组详情保留查询时间与高德来源。特色标签只是平台记录的描述，不等于当前菜单、商品可售或优惠有效。
- Tavily 搜索结果必须在标题或摘要中提及目标地点**完整名称**才作为网页线索展示；同品牌其他分店、仅提及商场的页面被过滤。即使名称命中，结果仍是 `identity_status=unverified`，不能作为同店菜单、套餐价格或营业状态的权威证据。
- 方案新增去程步行、完整活动时长、预算和当前营业四项可行性判断。仅真实去程路线且在约束内的项目为 `pass`；其余缺少可靠证据时为 `unknown`。前端显示地址、路线、商家记录及未知项，导航仍需明确确认并在生成高德链接前重新查询地点和路线。
- 将旧的流式 API 设想归档到 `backend/API_PROTOCOL_LEGACY.md`，`backend/API_PROTOCOL.md` 现在描述运行中的 JSON 与动作接口。

## 真实数据验证

- 配置好的真实 DeepSeek、高德、Tavily、Supabase PostgreSQL 链路，`scripts/verify_stage4_live.py` 得到 **3 个真实地点方案**，完成一次幂等保存、一次导航前路线重查与高德步行链接生成，并验证跨进程恢复、拒绝、过期和新输入失效。高德链接准备完成只代表 SoloVibe 的交接步骤，不证明高德客户端接收或用户到达。
- 单独查询上海徐家汇地铁站附近的一家具体咖啡分店，高德返回了街道地址、评分 **4.1**、参考人均 **38 元**、登记时段 **07:00–22:00**及特色标签。此处是接口返回的历史/参考资料，**没有**证明当下营业、实际消费或任何商品库存。
- Tavily 针对该分店的普通搜索返回品牌目录及商场概览；进一步检索美团/大众点评时返回大众点评的**其他分店**和泛化团购页，未检索到足以确认该目标分店当前菜单或套餐的页面。因此本轮不会展示“已查到该店套餐”的结论。
- `scripts/check.ps1` 的 Python 契约测试、TypeScript 类型检查和生产构建通过；默认浏览器用例通过，真实浏览器从聊天取得高德方案并在刷新后恢复。不同分店误匹配、供应商超时和地点身份冲突有隔离测试。

## 美团/大众点评的接入选择

美团技术服务合作中心提供门店商品、菜谱等接口，但所查到的相关接口标注**需要业务授权**，面向有门店/品牌授权的业务场景；目前项目没有相应授权令牌，不能把这些接口当成“凭一个普通 API Key 就能查任意商家”的通用数据源。大众点评原北极星开放平台已公告迁移至美团技术服务合作中心。未来如果取得适用的合作/商户授权，可新增独立适配器，并以分店 ID、授权范围和更新时间作为事实门槛。

Tavily 可用于**发现候选页面**，但检索摘要不保证同店、完整性或实时性。直接爬取美团/点评页面不是本轮默认路径：页面结构和访问控制可能变化，且在接入前需要核对目标来源的使用条件。更可控的补充来源是用户提供的商家官方页面或获得授权的数据供应商；仍必须进行同店识别和字段级溯源。

## 当前明确边界

本轮已完成真实地址解析、去程路线、导航链接交接，以及高德能够提供的分店基础资料。**完整菜单、当前套餐/优惠、实时营业、库存/座位、返程和完整活动时长尚未验证。** 当这些信息缺失时应用显示未知，不用高德参考人均判定预算一定满足。阶段五后续仍需局部重规划、断连恢复、数据删除、部署演练和更广泛的故障验证。
