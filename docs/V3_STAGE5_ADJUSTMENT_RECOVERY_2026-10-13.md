## 交付内容

用户可以直接修改预算、可用时间、最大步行时间、计划停留时间、偏好、避开项、所在位置和城市。修改请求带有 `expected_revision` 与 `request_id`：版本不一致会拒绝，相同请求只会重放先前结果。每次有效修改均创建新的运行和新的计划集，旧计划不会被覆盖。

系统按变更范围选择保守的证据复用策略：

| 用户修改 | 处理方式 |
| --- | --- |
| 降低预算、缩短时间、收紧步行、调整停留或精力 | 仅在地点事实、路线和公开资料均在 30 分钟时复用，再重新计算可行性。 |
| 修改返程地点 | 复用仍新鲜的地点事实和去程路线，只重新查询返程路线。 |
| 城市、出发位置、偏好、避开项，或放宽时间/步行范围 | 重新检索和规划。 |
| 点击单个门店“重查” | 只刷新该门店的地图详情、往返路线及可用公开来源。 |

复用不足以产生两个候选方案时，系统自动退回完整检索。每个计划 ID 带入新的运行 ID，因此同一地点在不同条件下也有独立、可追溯的计划版本。

## 恢复与反馈

新增运行状态、按请求 ID 查询、服务器时间线和用户反馈接口。页面重新加载后从服务端读取状态，不会盲目重发可能已执行的请求。所有查询按会话所有者隔离。

“考虑过”“去过”“没有去”“其他”反馈均以 `user_report` 保存；它们只表达用户自述，不能证明抵达、消费、预订、营业或商家库存。
